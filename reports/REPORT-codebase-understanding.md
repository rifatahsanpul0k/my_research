## 1. HOW THE CODEBASE IS ORGANIZED

### The core pattern: Generators → Notebooks → Kaggle → GitHub

```
scripts/gen_XXX_nb.py  →  notebooks/stageX_XXX.ipynb  →  Kaggle GPU  →  runs/XXX/
     (source)                  (build artifact)           (execution)      (results)
```

**Critical rule:** The `scripts/gen_*.py` files are the SOURCE OF TRUTH. The `.ipynb` files are generated by running the script. If you need to change a notebook, edit the generator script and re-run it. Never hand-edit notebook JSON.

**Why this pattern:** Notebooks run on Kaggle (which has the GPU and the private dataset). The generator pattern ensures reproducibility — anyone can rebuild the exact notebook from the script. It also makes code review possible (Python scripts are diffable, notebook JSON is not).

### The execution loop on Kaggle

Each notebook follows the same pattern:
1. **Setup cell:** Install packages, import libraries, detect GPU
2. **Git cell:** Clone the repo using `GITHUB_TOKEN` from Kaggle Secrets, set up push function
3. **Data cell:** Find the dataset via MARKER pattern (`10x_human_lymph_node_A1` folder), load GT (quarantined)
4. **Model/training cells:** Define architecture, train, save embeddings
5. **Eval cell:** Compute unsupervised metrics + quarantined post-hoc ARI
6. **Push cell:** `git add` → `git commit` → `git pull --rebase` → `git push`

**Push hygiene lessons (from AGENTS.md):**
- Commit BEFORE `pull --rebase`, never after
- Stage ALL changed files (including `registry.jsonl`), not just the combo folder
- Verify the OUTPUT notebook after generator edits (grep for stale tokens/paths)
- The git push token is scrubbed from error output (***)

### Shared modules (`pipeline/`)

| File | Purpose |
|------|---------|
| `pipeline/datasets.py` | Data loading: finds dataset root via MARKER, loads RNA/ADT/ATAC matrices, loads GT annotations |
| `pipeline/models.py` | Model architectures: SAGE/GAT encoders, fusion modules, shared-private splits, gating mechanisms |
| `pipeline/training.py` | Training loop: loss computation (reconstruction + spatial + disentanglement), optimizer, checkpointing |

These are imported by notebooks to avoid code duplication. If you change a model architecture, change it here (or in the notebook if it's experiment-specific).

### The unsupervised firewall (`tests/test_firewall.py`)

This is the most important test in the repo. It statically analyzes notebook code to verify:
- Ground-truth labels are NEVER used in training, preprocessing, graph construction, or model selection
- Labels are ONLY loaded for post-hoc ARI computation
- The declared-k exception is applied identically (not tuned per dataset)

**Every stage must pass this test before being accepted.** If you add label usage anywhere except `posthoc.json` computation, the test will catch it.

## 4. IS OUR APPROACH CORRECT? (Request for feedback)

### What we believe is correct

1. **The unsupervised firewall is non-negotiable and we're enforcing it correctly.** The test passes on every stage. The declared-k exception is the only label usage, applied identically, disclosed everywhere.

2. **RAUS v3b is the right selection criterion.** It's the only label-free rule we've found that positively correlates with ARI (ρ=0.512). Silhouette was proven harmful and removed.

3. **Exp0 was the right experiment.** It proved embeddings were better than reported and identified the clustering bottleneck. Zero training cost, massive information gain.

4. **Abandoning gated approaches was correct.** Three independent failures (S6-ONE, S6-ONE-v2, FRANK) with the same root cause (gates optimize reconstruction, not clustering). Continuing would be sunk-cost fallacy.

### What we're uncertain about

1. **Is the "ONE model" goal achievable?** The tissue divide (brain needs graph, lymph node hurt by it) is structural. Every attempt at a unified architecture has either failed or underperformed per-dataset specialists. Is there actually a single architecture that's best on all six, or is this goal impossible in principle?

2. **Is post-hoc ARI the right target?** We're optimizing for ARI against manual annotations. But annotations are imperfect, especially for developmental brain data (E11-E18). Are we overfitting to noisy labels?

3. **Is declared-k cheating?** We read k from ground-truth label counts. This is a form of label leakage, even though it's applied identically and disclosed. Should we be estimating k from the data instead? (e.g., via stability analysis across k values)

4. **Are we in a local optimum?** All our architectures are variations on SAGE/GAT + MLP fusion. The 11-paper review suggested fundamentally different approaches (optimal transport, diffusion models, contrastive learning) that we haven't seriously tried. Are we iterating on a dead end?

5. **The selector problem:** We proved that neither silhouette nor stability can select (transform, head) unsupervised. Does this mean unsupervised model selection is fundamentally limited, or just that we haven't found the right metric?

### Specific questions for the agent

1. Review `pipeline/models.py` — are there architectural bugs or missed opportunities in the SAGE/fusion implementation?
2. Review the Exp0 results — is there a pattern in (transform, head) winners that suggests a label-free selection rule we missed?
3. Is the preprocessing pipeline (especially ADT CLR and ATAC TF-IDF) optimal, or could better preprocessing unlock the human datasets?
4. Should we try estimating k from data instead of using declared-k? What method would you recommend?
5. Given the three gate failures, is there a fundamentally different way to achieve adaptive spatial weighting that doesn't rely on reconstruction-optimized gates?
